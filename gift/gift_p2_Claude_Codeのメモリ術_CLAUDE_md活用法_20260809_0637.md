# CLAUDE.md活用法 - 実践テンプレート

## この動画で学んだこと
モノレポで毎回同じ指示を繰り返す非効率を解消するため、`CLAUDE.md`にプロジェクトの指示を書き、ルートから階層まで自動で読み込ませる方法を学びました。

## すぐに使えるテンプレート

### 1. プロジェクト直下のCLAUDE.md（基本テンプレート）

```markdown
# プロジェクト指示書

## プロジェクト概要
- プロジェクト名: [プロジェクト名]
- 技術スタック: [使用技術]
- ビルドコマンド: `npm run build`

## コーディング規約
- インデント: スペース2つ
- 命名規則: camelCase（変数・関数）、PascalCase（コンポーネント）
- セミコロン: 必須
- クォート: シングルクォート

## よく使うコマンド
- 開発サーバー: `npm run dev`
- テスト: `npm test`
- リント: `npm run lint`

## 注意事項
- 既存のコードスタイルを尊重すること
- 変更前に必ずテストを実行すること
- コミットメッセージは日本語で書くこと
```

### 2. サブディレクトリ用CLAUDE.md（階層別設定）

```markdown
# フロントエンド固有の指示

## ディレクトリ構造
- `src/components/` - 再利用可能なUIコンポーネント
- `src/pages/` - ページコンポーネント
- `src/hooks/` - カスタムフック

## フロントエンド固有ルール
- コンポーネントは関数コンポーネントで実装
- スタイリングはCSS Modulesを使用
- 状態管理はZustandを使用

## テスト要件
- コンポーネントテストはTesting Libraryを使用
- スナップショットテストは不要
```

### 3. モノレポ構成例

```
monorepo/
├── CLAUDE.md          # ルート設定（全体共通）
├── packages/
│   ├── frontend/
│   │   ├── CLAUDE.md  # フロントエンド固有設定
│   │   └── src/
│   └── backend/
│       ├── CLAUDE.md  # バックエンド固有設定
│       └── src/
└── docs/
    └── CLAUDE.md      # ドキュメント用設定
```

### 4. 実践的なCLAUDE.md（完全版）

```markdown
# モノレポ全体の指示書

## プロジェクト構成
- フロントエンド: React + TypeScript
- バックエンド: Node.js + Express
- 共通パッケージ: shared/

## 共通コマンド
- 全パッケージのインストール: `npm install`
- ビルド: `npm run build`
- テスト: `npm test`

## 開発フロー
1. ブランチ名: `feature/機能名` or `fix/修正内容`
2. コミットメッセージ: `[種別] 変更内容`（例: `[feat] ログイン機能を追加`）
3. PR作成前に: リント・テスト・ビルドを必ず実行

## コーディング規約
- TypeScriptの型定義を必ず行う
- エラーハンドリングを必ず実装
- コメントは日本語で記述

## 環境変数
- `.env.example`を参照し、必要な環境変数を設定
- 機密情報はコミットしない

## デプロイ
- 本番環境: `npm run deploy:prod`
- ステージング: `npm run deploy:staging`
```

## 使い方
1. プロジェクトのルートディレクトリに`CLAUDE.md`ファイルを作成
2. 上記テンプレートをコピーし、プロジェクトに合わせてカスタマイズ
3. サブディレクトリに固有の設定が必要な場合は、そのディレクトリにも`CLAUDE.md`を作成
4. Claude Codeを起動すると、自動的にルートから階層まで読み込まれます
5. 指示が変わった場合は、`CLAUDE.md`を編集するだけで反映されます

## よくある質問

**Q: CLAUDE.mdはどこに置けばいいですか？**
A: プロジェクトのルートディレクトリに置くのが基本です。サブディレクトリに置くと、そのディレクトリ内でのみ有効な設定になります。

**Q: 複数のCLAUDE.mdがある場合、優先順位はどうなりますか？**
A: 現在の作業ディレクトリに最も近いCLAUDE.mdが優先されます。ルートの設定をベースに、サブディレクトリの設定が上書きされます。

**Q: チームメンバーとCLAUDE.mdを共有できますか？**
A: はい、CLAUDE.mdをGitリポジトリにコミットすれば、チーム全員で共有できます。プロジェクトの知識をコードとして管理できます。

**Q: 動画で紹介されたAncestor Loadingとは何ですか？**
A: 現在のディレクトリから親ディレクトリへ遡って、すべてのCLAUDE.mdを自動的に読み込む機能です。モノレポで特に便利です。
