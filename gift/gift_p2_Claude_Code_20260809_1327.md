# Claude Codeで毎回の指示が不要になる設定 - 実践テンプレート

## この動画で学んだこと
プロジェクト直下に`CLAUDE.md`ファイルを作成し、コーディング規約や禁止事項を記述することで、毎回の指示入力を省略し、Claude Codeが常にその設定を自動的に読み込んで作業してくれるようになります。

## すぐに使えるテンプレート

### 1. プロジェクトルートに`CLAUDE.md`を作成

```markdown
# プロジェクト設定（Claude Code用）

## プロジェクト概要
- プロジェクト名: [プロジェクト名を記入]
- 技術スタック: [使用技術を記入（例: React, TypeScript, Node.js）]
- プロジェクトの目的: [プロジェクトの目的を簡潔に記入]

## コーディング規約

### 全般
- インデントはスペース2つを使用する
- 文字列はシングルクォートを使用する
- セミコロンは必須とする
- 変数名・関数名はキャメルケースで記述する
- 定数はUPPER_SNAKE_CASEで記述する
- クラス名はパスカルケースで記述する

### ファイル構成
- コンポーネントは`src/components/`配下に配置する
- ページは`src/pages/`配下に配置する
- ユーティリティ関数は`src/utils/`配下に配置する
- 型定義は`src/types/`配下に配置する

### コメント
- 複雑なロジックには必ず日本語でコメントを付ける
- TODOコメントは`TODO: 内容`の形式で記述する
- 関数の目的が不明確な場合はJSDoc形式で説明を追加する

## 禁止事項
- `any`型の使用は禁止する
- `console.log`の本番コードへの残置は禁止する
- 未使用のインポート・変数を残さない
- ハードコードされたAPIキーや認証情報をコミットしない
- エラーハンドリングを無視したコードを書かない

## テスト規約
- テストフレームワーク: [テストフレームワークを記入（例: Jest, Vitest）]
- テストファイルは`__tests__/`ディレクトリまたは`.test.ts`ファイルに配置する
- 新機能を追加する場合は必ずテストを作成する
- テストは日本語でテストケース名を記述する

## コミットメッセージ規約
- プレフィックス: `feat:`, `fix:`, `docs:`, `style:`, `refactor:`, `test:`, `chore:`
- 日本語で変更内容を簡潔に記述する
- 例: `feat: ユーザー認証機能を追加`

## 環境情報
- Node.jsバージョン: [バージョン記入]
- パッケージマネージャー: [npm / yarn / pnpm]
- ビルドツール: [Vite / Webpack / Next.js など]

## その他
- 使用するライブラリのバージョンは`package.json`で固定する
- コードレビュー時は上記規約に従っているか確認する
- 不明な点があれば日本語で質問する
```

```bash

# プロンプトで以下のように指示してみる
# 「このプロジェクトのコーディング規約に従って、新しいコンポーネントを作成してください」
```

## 使い方

1. **プロジェクトのルートディレクトリに移動**します
2. **`CLAUDE.md`ファイルを作成**し、上記テンプレートをコピー＆ペーストします
3. **プロジェクトに合わせて内容をカスタマイズ**します（技術スタック、規約、禁止事項など）
4. **Claude Codeを起動**すると、自動的に`CLAUDE.md`の内容が読み込まれます
5. **通常通り指示を出すだけ**で、毎回規約を説明する必要がなくなります

## よくある質問

**Q: プロジェクトごとに異なる設定をしたい場合は？**
A: 各プロジェクトのルートディレクトリに`CLAUDE.md`を配置することで、プロジェクトごとに異なる設定が可能です。Claude Codeは現在のディレクトリの`CLAUDE.md`を自動的に読み込みます。

**Q: グローバルな設定もできますか？**
A: はい、ホームディレクトリ（`~/.claude/CLAUDE.md`）に配置することで、すべてのプロジェクトに適用されるグローバル設定が可能です。プロジェクト固有の設定はプロジェクト直下の`CLAUDE.md`に記述します。

**Q: 設定を変更した場合、反映には再起動が必要ですか？**
A: いいえ、`CLAUDE.md`を保存すると、次回のClaude Codeセッションから自動的に反映されます。現在のセッション中に変更を反映したい場合は、`/clear`コマンドで会話をリセットしてください。

**Q: マークダウン以外の形式でも記述できますか？**
A: `CLAUDE.md`はマークダウン形式が推奨されていますが、プレーンテキストでも動作します。ただし、見やすさや構造化の観点からマークダウン形式をおすすめします。
