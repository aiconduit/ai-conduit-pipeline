# CLAUDE.md活用法 - 実践テンプレート

## この動画で学んだこと
モノレポで毎回同じ指示を繰り返す非効率を解消するため、`CLAUDE.md`にプロジェクトの指示を書き、ルートから階層まで自動で読み込ませる方法を学びました。

## すぐに使えるテンプレート

### 1. プロジェクト直下のCLAUDE.md（基本形）

```markdown
# プロジェクト指示書

## プロジェクト概要
- このリポジトリはモノレポ構成です
- フロントエンド: Next.js / TypeScript
- バックエンド: NestJS / TypeScript
- インフラ: AWS (CDK)

## 開発ルール
- コミットメッセージは Conventional Commits に従う
- テストは必ず書く（カバレッジ80%以上）
- 型定義は必ず明示する（any禁止）

## コマンド
- 開発サーバー: `npm run dev`
- テスト: `npm test`
- ビルド: `npm run build`

## 注意事項
- 環境変数は `.env.local` に管理
- APIの変更時は OpenAPI ドキュメントも更新
```

### 2. サブディレクトリ用CLAUDE.md（階層別設定）

```markdown
# フロントエンド固有の指示

## 技術スタック
- Next.js 14 (App Router)
- Tailwind CSS
- React Query

## コーディング規約
- コンポーネントは `components/` 配下に配置
- 状態管理は React Query を使用
- スタイルは Tailwind のユーティリティクラスを使用

## テスト
- Jest + React Testing Library
- コンポーネントテストは `__tests__` フォルダに配置
```

### 3. ルートCLAUDE.md（Ancestor Loading用）

```markdown
# モノレポ全体の指示

## リポジトリ構造
```
apps/
  web/          # フロントエンド
  api/          # バックエンド
packages/
  shared/       # 共有パッケージ
  ui/           # UIコンポーネント
```

## 共通ルール
- パッケージ管理: npm workspaces
- コードフォーマット: Prettier
- Lint: ESLint

## 環境構築
1. `npm install` をルートで実行
2. `npm run dev` で全アプリ起動
3. 環境変数は各アプリの `.env` に設定
```

### 4. 便利なCLAUDE.md設定例

```markdown
# プロジェクト設定

## 自動化ルール
- コードレビュー時はセキュリティ面も確認
- パフォーマンス改善の提案を積極的に行う
- リファクタリングの提案は具体的なコード例付きで

## ファイル操作ルール
- ファイル作成時は関連ファイルも確認
- 削除時は依存関係をチェック
- リネーム時は参照箇所を全て更新

## コミュニケーション
- 日本語で回答
- コード例は必ず含める
- 変更理由を明確に説明
```

## 使い方

1. **ルートCLAUDE.mdの作成**: モノレポのルートディレクトリに`CLAUDE.md`を作成し、プロジェクト全体のルールを記述
2. **階層別CLAUDE.mdの作成**: 各サブディレクトリ（apps/web、apps/apiなど）に固有の指示を記述
3. **自動読み込みの確認**: Claude Codeを起動し、各ディレクトリで指示が自動適用されることを確認
4. **反復的な指示の排除**: 毎回同じ指示を書く代わりに、CLAUDE.mdに集約
5. **チームでの共有**: CLAUDE.mdをGitで管理し、チーム全員で同じ設定を共有

## よくある質問

**Q: CLAUDE.mdはどこに置けばいいですか？**
A: プロジェクトのルートディレクトリに置くのが基本です。サブディレクトリに置くと、そのディレクトリ内でのみ有効な設定になります。Ancestor Loadingにより、上位階層のCLAUDE.mdも自動で読み込まれます。

**Q: 複数のCLAUDE.mdがある場合、優先順位はどうなりますか？**
A: 現在のディレクトリに最も近いCLAUDE.mdが優先されます。ルートの設定をベースに、サブディレクトリの設定が上書きする形になります。

**Q: CLAUDE.mdの変更は即座に反映されますか？**
A: はい、Claude Codeを再起動するか、新しいセッションを開始すると反映されます。編集中のセッションには影響しないので注意してください。

**Q: モノレポ以外でも使えますか？**
A: もちろんです。単一のプロジェクトでも、チームのコーディング規約や開発ルールをCLAUDE.mdにまとめることで、一貫性のある開発が可能になります。
