#### ① コードレビュー3分マジック（動画で紹介した方法）

```bash
# 変更ファイル全体をレビュー
/review

# 特定のファイルを重点的にレビュー
/review src/auth/login.ts

# セキュリティ重視のレビュー
/review --security --strict

# 変更箇所だけをチェック（最速）
/review --diff
```

**プロンプト例（より詳細なレビューが欲しい場合）:**
```
このPRの変更点をレビューして。特に以下をチェックして：
1. セキュリティホール（SQLインジェクション、XSSなど）
2. パフォーマンスの問題（N+1クエリ、不要なレンダリング）
3. バグの可能性（境界値、null/undefined処理）
4. 命名規則や可読性
修正案も具体的なコードで提案して。
```

#### ② あなた専用のレビュールールを作る（精度UPの秘訣）

`.claude/rules/review.md` を作成：

```markdown
# コードレビュールール

## 必須チェック項目
- [ ] エラーハンドリングが適切か（try-catch、エラーメッセージ）
- [ ] ログが適切に出力されているか
- [ ] 型定義が正確か（any を避けているか）
- [ ] テストコードが存在するか

## 禁止事項
- コメントアウトされたコードを残さない
- マジックナンバーを直接書かない
- console.log を本番コードに残さない

## プロジェクト固有ルール
- 関数名は camelCase で記述
- APIレスポンスは /src/api/types.ts に定義
- エラーメッセージは日本語で統一
```

**使い方:**
```
このファイルを読んで、以下の変更をレビューして。
```
→ あなたのチームのルールに沿ったレビューが自動で行われます！

#### ③ コミットメッセージ自動作成コマンド

```bash
# 変更されたファイルを確認
git diff --stat

# Claude Codeでコミットメッセージを自動作成
この変更に合うコミットメッセージを3パターン提案して。
規約に従って（例: feat:, fix:, chore: のプレフィックス）

# もっと簡単な方法
/commit
```

**出力例:**
```
1. feat(auth): JWTトークンのリフレッシュ機能を追加
2. fix(api): レート制限のバグを修正し429エラーを適切に処理
3. refactor: 認証ミドルウェアの共通化とテスト追加
```

#### ⑤ プロジェクト全体を把握したレビュアー構築法

**ステップ1: プロジェクト概要をClaude Codeに教える**
```bash
# プロジェクトのREADMEを要約させる
README.mdを要約して、プロジェクトの目的・技術スタック・ディレクトリ構造を教えて。

# 全体アーキテクチャを把握
srcディレクトリの構造を把握して、各モジュールの役割を整理して。
```

**ステップ2: CLAUDE.mdを作成して常に読ませる**
```markdown
# CLAUDE.md - プロジェクト永続知識

## プロジェクト概要
- Next.js 14 + TypeScript + Prisma のECサイト
- 認証は NextAuth.js、決済は Stripe

## 技術スタック
- フロント: React 18, Tailwind CSS
- バック: Next.js API Routes, Prisma ORM
- DB: PostgreSQL, Redis（キャッシュ）

## コード規約
- コンポーネントは app/components/ に配置
- APIエンドポイントは app/api/ に配置
- 環境変数は .env.local で管理

## 注意点
- Prismaマイグレーション時は必ず npx prisma generate を実行
- テストは vitest で app/__tests__/ に作成
```

### ⚡ 時短ワザ：よく使うレビューをカスタムコマンド化

`.claude/commands/review-full.md` を作成：

```markdown
---
description: フルレビュー（セキュリティ+パフォーマンス+テスト）
---

レビュー対象: $ARGUMENTS

以下の観点で詳細レビューを実施して：
1. セキュリティ（OWASP Top 10 + インジェクション対策）
2. パフォーマンス（Big O、N+1問題、メモリリーク）
3. テスト品質（カバレッジ、エッジケース）
4. 保守性（複雑度、命名、コメント）
5. 既存コードとの整合性（CLAUDE.mdを参照）

出力形式：
- 問題点を「重大度（高/中/低）× 修正難易度（高/中/低）」で分類
- 修正提案は具体的なコードで提示
- 最後に修正優先度のまとめ表
```

**使い方:**
```bash
/review-full src/auth/login.ts
```
